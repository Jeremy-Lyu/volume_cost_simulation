# 项目总览

数字都是示例，不是任何工厂的实绩。标 ⚠ 的还没经业务确认。现行代码在 `v5.2/`，归档代码在 `archive/`。

这份总览说明现在算到哪。选择怎么读看 [设计说明.md](设计说明.md)。公式先看哪一章看 [手册/先读.md](手册/先读.md)。改表看 `工厂改数与重算指南.md`。背景和四个问题在仓库首页 [README.md](../README.md)。

## 背景与需求

工厂排一年的产量，每个车间每个月要定开多快、开几班。计划、IE、人事、能源和财务各自掌握订单、JPH、工资、电价和制造费用。需求、电价、停线或加人速度变了以后，班次改在哪、差额落在哪几个科目，需要同一份配置包才能对齐。

这个仓库用示例配置包把这件事做成可重复的求解。默认目标是成本最低。稳定优先和保人力是在这个目标上再加约束。换厂时换配置包目录，求解代码不动。哪些假设还没确认，写在 `v5.2/data/假设登记表.md`。

---

## 1. 模型在回答什么

每个车间、每个月选一个 JPH × 班次，使成本最小。选择怎么读、固定费用为什么不跟班次消失、哪些差额还不能说成已经省下，写在 [设计说明.md](设计说明.md)。这一页只记现在算到哪。

## 2. 现在算到哪

| 层 | 现状 |
| :-- | :-- |
| 月度选档 | `v5.2/run.py`：基准、需求 ±10%、电价 +20%、工资 +5%。手册记载的 v5.2 基准约 44,288 万元、12 万台（示例）。2026-10-19 再跑约 44,287 万元，差在求解容差里 |
| 人工弹性 | `labor_flex.csv`：停工日可省比例 φ = 0.44 ⚠。派遣比 20% 只能当成派遣加临时工，法规派遣上限是 10% |
| 换档 | `jph_switch.csv`：示例 30 万元/次，并损失 2 天产出 ⚠ |
| 借调 | 月度按人·天凑平，净额偏乐观。按天核对焊装和涂装同一天开工时，借调可以是 0。月度净额不要当成已落实的节约 |
| 能源 | 电已拆成运行、待机、需量；涂装有天然气和启停炉。水、蒸汽、压缩空气没有分表，就没有单列 |
| 按天 | `daily.py` 只覆盖一个月里的焊装 → 白车身缓存 → 涂装，用来核对开停和借调，不替代全年月度方案 |
| 周序列 | `weekly.py` 出顺序和换色。默认不改月计划；`--apply` 才把槽位上限写回并重解一次 |
| 策略 | `strategies.py` 三种：成本优先、稳定优先、保人力。场景库和 `factory_analysis.py` 用来问「如果发生某件事」 |
| 全成本 | 可选表缺了就不启用，基础口径不变。物料只进报表，不进目标；有 `margin.csv` 时目标改为成本减边际贡献。启用折旧时要从制造费用里扣除，避免重复 |
| 多工厂 | 换配置包目录，不改求解代码。第二厂目前只有虚构的 `plants/DEMO_B` |
| 对账 | 有 `actual.csv` 时 `run_plant.py` 按车间×月比产量，示例阈值 ±5% ⚠。成本、人数、加班的实际值还没接进来 |

2026-10-17 文稿里的基准 42,953 万元、单车 3,579 元，是更早原型、还没加上后来规则时的示例。不要和 v5.2 的 44,288 万元放在一张对比表里当同口径。

求解时限写在 `global_params.csv`（示例 120 秒）。到时限仍可能打印 Optimal，需求 −10% 曾经比 golden 高出约 189 万元，那是停在另一个可行解上。

## 3. 十个方向，各自停在哪

这些方向来自 2026-10-17 的拓展稿。下面是对到 `v5.2` 之后的状态。

| 方向 | 现在 |
| :-- | :-- |
| 1 换成工厂自己的数，并和实际对账 | 机制有了（配置包、`plant_check`、`actual.csv`）。表里仍是示例，来源和负责人见 `v5.2/data/data_source_map.csv`，多数口径仍是「待确认」 |
| 2 月定档、周排班、日排人 | 月度在跑。周序列和按天开停各有第一版。技能只做事后检查，不进月度求解 |
| 3 JPH 档内微调、车型组合折损 | 仍是离散档。爬坡可用 `ramp.csv`。组合折损没有参数 |
| 4 用边际贡献代替拍脑袋的缺货惩罚 | `margin.csv` 可选。没配这张表时仍用 `shortage_penalty` |
| 5 把波动做成每月例行体检 | `lab/run_v5.py` 能做权重扫描、蒙特卡洛和稳健方案，耗时长，没有接进每月例行 |
| 6 物料和物流进全成本 | 可选表已接上。物料不进目标，避免模型为了少花钱而停产。发运上限必须同时有成品库 |
| 7 用规则或模型解释结果 | 演示页和 `factory_analysis.py` 用规则填数。语言润色不参与求解，也不改参数 |
| 8 从 CSV 换成平台 | 仍是本机 CSV 加 PuLP 2.9 |
| 9 复制到第二个真实工厂 | 配置包可以换厂。还没有第二个真实工厂的数 |
| 10 每月发布、测算、对账、校准 | 步骤写在第 4 节，组织节奏还没运转 |

知识库没回来之前不要写进求解器的，包括：建造周订单、零件级叫料公式、在途分段、安全缓冲的正式公式、颜色批量的业务规则、排序规则、带币种的零件价生效、VIN 断点。技能矩阵、再拆一档出勤、碳市场、每车间一条返修线、用成本曲线做跨厂结算、把关税写进月度模型，当前也不做。

## 4. 业务上怎么转一圈

```
需求与参数 → 检查配置包 → 求解（基准 / 场景 / 策略）→ 看人工和能源差额 → 选定方案
        ↑                                                              |
        └──────── 有实际产量时对账，偏差回到参数，升一版配置 ──────────┘
```

参数归属沿用当时的建议，确认前都是 ⚠：工时和 JPH 归 IE，工资和加班归 HR，电价和气价归能源，制造费用、班车、外包归财务，需求、日历和产能上限归计划。停工日发薪、派遣口径、换档费用归人事、财务和工艺共同确认，记在 `v5.2/data/假设登记表.md`。

作业标准（标准化作业、工时文件、质量指标、变更生效）留在本机，不进仓库。那些对象还没换成工厂自己的编码和阈值。定员继续用示例表，直到 IE 确认它来自平衡方案。
