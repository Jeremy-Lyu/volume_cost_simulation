# 设计说明

数字都是示例，配置包 `TZ-cfg-2026.10-示例`。这一页说明设计原则：模型替谁做决定、钱看哪几个科目、哪些话还不能说成已经省下。公式和改表步骤在后面的案例、指南和手册里。

## 1. 它替人做的决定

每个车间、每个月只选一个档：**JPH × 班次**。班次可以是 0（整月停线）、1、2 或 3。示例车间链是冲压 → 焊装 → 涂装 → 总装，需求落在总装。

产能按这条链乘出来：JPH × 开动小时 × 开动率 × OEE × 出勤 × 爬坡。没启用返修区时再乘一次合格率。加班产量用同一套系数。车间之间用缓存接产量：上月库存 + 本月上游产量 = 本月下游消耗 + 本月库存。

求解器在这些约束下让成本最低。稳定优先、保人力是在这个目标上再加约束，定义在 `v5.2/strategies.py`。权重扫描在 `v5.2/lab/strategy_v5.py`，它的「成本优先」和精解差大约 9 万，两套差额不要写进同一张决策卡。

物料如果配了表，只进报表，不进这个目标，避免为了少花钱而停产。配了 `margin.csv` 之后，目标改为成本减去边际贡献。

## 2. 钱看哪几个科目

固定制造费用不跟着班次消失。产量不变时，总成本几乎不动，要看的是人工、加班、能源和停工日。产量变了以后，单车成本升降多半是固定费用被摊薄或摊厚。

示例基准（`run.py`，总成本）约 44,287 万元、年产量 12 万台、单车 3,691 元。工作台决策卡的运营成本是 44,289 万元。这套示例没有边际贡献，基准没有流失，两套数只差在取整。场景卡对照基准运营成本。策略卡对照 `strategies.py` 里的成本优先。两张卡的差额不要加在一起。

一次实践按这个顺序读：[样例/设计走读.md](样例/设计走读.md) 用基准的 10 月把「选一个档」对到需求、定员和固定费用上。[案例解析.md](案例解析.md) 再用「9–12 月需求 +15%」和电价上浮走完旋钮、班次和科目。五个标准场景和「开停校正」决策卡也在 [样例/](样例/)，不必先求解。

## 3. 哪些话还不能说成已经省下

月度借调按人·天凑平，净额偏乐观。按天核对只覆盖一个月里的焊装、白车身缓存和涂装；焊装和涂装同一天开工时，借调可以是 0。决策卡上，借调净额达到 50 万元就标**未验证**，运营成本数字仍保留。示例基准的借调净额约 −892 万，已经标了未验证。

六个粗参数在 `v5.2/data/coarse_params.csv`，默认不改变现成本。场景「开停校正」才打开示例值：招聘月增 5%、月降 15%、换档后首月效率 0.85、计划维修 2 天、起订加急 50 万元、复产质量 5 万元，全部 ⚠。这次示例里，运营成本 44,625 万，比基准高 336 万。会改建议的是换档后首月效率。

全年方案是月度模型。周序列默认只出顺序和换色，加上 `--apply` 才把槽位上限写回并重解一次。设备保持车间平均。假设 A12 的回测门槛是 2%–3%，状态未测；偏差落到这个区间，才书面确认继续不拆到每台设备。`run_plant.py` 现在的对账阈值仍是 ±5%。

## 4. 基数：每一类是什么量级、谁改

下表是示例包里的角色，不是工厂实绩。每一格的口径状态在 [`v5.2/data/data_source_map.csv`](../v5.2/data/data_source_map.csv)，多数仍是「自设值」或「待确认」。改完按 [工厂改数与重算指南.md](工厂改数与重算指南.md)。

| 一类数 | 示例里长什么样 | 谁改 | 在哪张表 |
| :-- | :-- | :-- | :-- |
| 需求 | 全年约 12 万台，按车型分到 12 个月 | 计划 | `demand.csv` |
| JPH 与定员 | 每个车间几档，每档对应人数和功率 | IE | `jph_options.csv` |
| 班次与日历 | 0–3 班、每月工作日 | 计划 / IE | `shift_options.csv`、`calendar.csv` |
| 工资与加班 | 月薪、标准月工时、加班倍数。加班单价由这三项派生，单独改加班单价那一格不会变结果 | 人事 | `global_params.csv` |
| 能源 | 分时电价、天然气、待机、启停、需量。水、蒸汽、压缩空气没有分表，就没有单列 | 能源 / 设备 | `energy_config.json`、`shop_energy.csv`、`tou_*.csv` |
| 制造费用、缓存、持有 | 不跟班次消失的固定费用，以及车间之间的库存 | 财务 / 物流 | `shop_params.csv` 及可选扩展表 |

换工厂时把 `v5.2/data/` 复制成 `v5.2/plants/本厂代号/`，改 `plant.json` 的配置版本。求解代码不动。不要运行 `gen_data.py`，它会覆盖已经填好的表。

## 5. 业务假设

尚未确认的判断在 [`v5.2/data/假设登记表.md`](../v5.2/data/假设登记表.md)。标 ⚠ 的还不能写成工厂规定。

| 编号 | 在考虑什么 | 示例里怎么处理 |
| :-- | :-- | :-- |
| A01 | 派遣加临时工占比 20%。法规派遣上限是 10%，20% 只能按合计口径理解 | 写在 `labor_flex.csv`，停工日可省比例 φ = 0.44 |
| A02 | 停工日发薪：正式工 70%，派遣 0% | 发薪越高，停线省得越少 |
| A03 | 跨车间借调上限 10% | 月度净额达到 50 万元标未验证 |
| A04 | 换一次 JPH 档：30 万元，并损失 2 天产出 | 换档越贵，越倾向用加班或停工日调节 |
| A05–A10 | 招聘快慢、学习曲线、计划维修、起订加急、复产质量 | 默认关闭。场景「开停校正」才用示例值 |
| A07 | 车型混线 | 仍按总量。回测偏差超过 3% 再考虑节拍系数 |
| A11 | 电压、购电、气价、班次时刻、启停 | 能源参数，待工厂确认 |
| A12 | 平均化是否还站得住 | 门槛 2%–3%，未测 |
