# 设计说明

数字都是示例，配置包 `TZ-cfg-2026.10-示例`。这一页只讲一件事：模型替人做的那个选择，以及哪些差额还不能说成已经省下。公式底稿在 [手册/先读.md](手册/先读.md)。

## 1. 先看懂这一个选择

工厂排一年的产量。每个车间、每个月只做一次选择：开多快、开几班。班次可以是 0（整月停线）、1、2 或 3。示例车间是冲压 → 焊装 → 涂装 → 总装。订单记在总装上。

求解器在交得上货的前提下，挑全年成本最低的那些档。它不另算一套利润。物料如果以后配了表，只出现在报表里，不进这个目标。

用已经解出的基准看 10 月。这一月四个车间选的档不一样，所以适合当例子。来源是样例里的 `results_summary.md`，这里不重新求解。

| 车间 | 10 月选中 |
| :-- | :-- |
| 冲压 | 50 JPH × 2 班 |
| 焊装 | 36 JPH × 2 班 |
| 涂装 | 36 JPH × 3 班 |
| 总装 | 36 JPH × 2 班 |

这一月总装订单是 4,620 + 3,630 + 2,750 = 11,000 台。四个车间每个月的固定制造费用是 120 万、200 万、250 万、220 万，加起来 790 万。模型乘 12 个月，全年 9,480 万。10 月冲压开两班、涂装开三班，这 790 万仍然计入。

所以产量不变时，要看人工、加班、能源和停工日。产量变了以后，单车成本升降多半是这 9,480 万被摊薄或摊厚。

每个车间本来有三档 JPH（冲压 30 / 40 / 50，其余 24 / 30 / 36）和四种班次。求解器每个车间只留下一行。10 月没有车间选 0 班。冲压这一月 JPH 仍是 50，变的是班次，不要读成换了一档速度。

格子从哪张表来、加班单价怎么由月薪派生，写在 [样例/设计走读.md](样例/设计走读.md)。

## 2. 对外只引用这一句

示例配置包下，基准总成本 44,287 万元、12 万台、单车 3,691 元。旺季四个月需求 +15% 时，运营成本比基准 44,289 万元多 1,897 万元，多交付 6,525 台。借调净额未验证，不写入节约。

`run.py` 印的是总成本 44,287 万元。工作台决策卡印的是运营成本 44,289 万元。这套示例没有边际贡献，基准没有流失，两套数只差在取整。场景卡对照 44,289。策略卡对照 `strategies.py` 里的成本优先。两张卡的差额不要加在一起。

词的定义在 [术语与口径.md](术语与口径.md)。改一个输入看单车和旺季差额，用 [样例/成本模型_示例.xlsx](样例/成本模型_示例.xlsx)。那张表不重新求解。

## 3. 一次求解在做什么

1. 冻住一份表：需求、日历、JPH 与定员、单价，以及可选的扩展表。
2. 每个候选档算产能：JPH × 开动小时 × 开动率 × OEE × 出勤 × 爬坡。没启用返修区时再乘一次合格率。加班产量用同一套系数。
3. 把人工、能源、班车、外包、制造费用、库存持有和缺货惩罚加总。加班单价由月薪 ÷ 标准月工时 × 倍数派生，示例约 77.6 元/小时。单独改一个名叫「加班单价」的格子，结果不会变。
4. 在约束下留下成本最低的档，写出每车间每月的班次和科目。

车间之间用缓存接产量：上月库存 + 本月上游产量 = 本月下游消耗 + 本月库存。不要用 11,000 去除以 JPH，手算成「10 月一定要开几班」。

稳定优先、保人力是在同一次求解上再加约束，定义在 `v5.2/strategies.py`。权重扫描在 `v5.2/lab/strategy_v5.py`，它的「成本优先」和精解差大约 9 万，不要写进同一张决策卡。

## 4. 三件不要说成已经省下

**借调。** 月度按人·天凑平，净额偏乐观。按天核对只覆盖一个月里的焊装、白车身缓存和涂装。焊装和涂装同一天开工时，借调可以是 0。决策卡上，净额达到 50 万元就标未验证，运营成本数字仍保留。示例基准的借调净额约 −892 万。手册里更早一次求解写过净 −833 万，那是另一次示例，不要和 −892 万放在一张表里当同一笔节约。

**六个粗参数。** `v5.2/data/coarse_params.csv` 默认不改变现成本。场景「开停校正」才打开示例值：招聘月增 5%、月降 15%、换档后首月效率 0.85、计划维修 2 天、起订加急 50 万元、复产质量 5 万元，全部 ⚠。那张卡的运营成本是 44,625 万，比基准运营成本 44,289 万高 336 万。会改建议的是换档后首月效率。

**按天和按周。** 全年方案是月度模型。按天只核对一个月。周序列默认只出顺序和换色，加上 `--apply` 才把槽位上限写回并重解一次。设备保持车间平均。假设 A12 的回测门槛是 2%–3%，状态未测。`run_plant.py` 现在的对账阈值仍是 ±5%。

## 5. 基数：每一类是什么量级、谁改

下表是示例包里的角色，不是工厂实绩。每一格的口径状态在 [`v5.2/data/data_source_map.csv`](../v5.2/data/data_source_map.csv)，多数仍是「自设值」或「待确认」。改完按 [工厂改数与重算指南.md](工厂改数与重算指南.md)。

| 一类数 | 示例里长什么样 | 谁改 | 在哪张表 |
| :-- | :-- | :-- | :-- |
| 需求 | 全年约 12 万台，按车型分到 12 个月 | 计划 | `demand.csv` |
| JPH 与定员 | 每个车间几档，每档对应人数和功率 | IE | `jph_options.csv` |
| 班次与日历 | 0–3 班、每月工作日 | 计划 / IE | `shift_options.csv`、`calendar.csv` |
| 工资与加班 | 月薪、标准月工时、加班倍数 | 人事 | `global_params.csv` |
| 能源 | 分时电价、天然气、待机、启停、需量。水、蒸汽、压缩空气没有分表，就没有单列 | 能源 / 设备 | `energy_config.json`、`shop_energy.csv`、`tou_*.csv` |
| 制造费用、缓存、持有 | 不跟班次消失的固定费用，以及车间之间的库存 | 财务 / 物流 | `shop_params.csv` 及可选扩展表 |

换工厂时把 `v5.2/data/` 复制成 `v5.2/plants/本厂代号/`，改 `plant.json` 的配置版本。求解代码不动。不要运行 `gen_data.py`，它会覆盖已经填好的表。

## 6. 还没确认的假设

尚未确认的判断在 [`v5.2/data/假设登记表.md`](../v5.2/data/假设登记表.md)。标 ⚠ 的还不能写成工厂规定。读结果时最容易混的是这四条：

| 编号 | 在考虑什么 | 示例里怎么处理 |
| :-- | :-- | :-- |
| A01 | 派遣加临时工占比 20%。法规派遣上限是 10%，20% 只能按合计口径理解 | 写在 `labor_flex.csv`。停工日可省比例 = 0.20×(1−0) + 0.80×(1−0.70) = 0.44 |
| A03 | 跨车间借调上限 10% | 月度净额达到 50 万元标未验证 |
| A04 | 换一次 JPH 档：30 万元，并损失 2 天产出 | 换档越贵，越倾向用加班或停工日调节 |
| A05–A10 | 招聘快慢、学习曲线、计划维修、起订加急、复产质量 | 默认关闭。场景「开停校正」才用示例值 |

A02、A07、A11、A12 的原文在假设登记表。为什么物料不进目标、为什么全年以月度方案为准、为什么借调净额不改运营成本，写在 [决策记录/](决策记录/)。

## 7. 代码从哪进

月度模型只有 `v5.2/model_builder.py` 一份。日常命令都经 `v5.2/engine.py` 进去。

| 要做什么 | 命令 | 入口 |
| :-- | :-- | :-- |
| 五个标准场景 | `run.py` | `engine.solved`：解一次，不读缓存 |
| 换一份配置包 | `run_plant.py` | 同上 |
| 成本优先 / 稳定优先 / 保人力 | `strategies.py` | 同上，额外约束传进同一次求解 |
| 决策卡、快速重算、权重扫描 | 工作台、`run_quick.py`、`lab/` | `engine.solve_case`：同一个模型，同参数第二次读缓存 |
| 核对一个月的开停 | `daily.py` | 另一张小模型，不替代全年 |
| 周顺序和换色 | `weekly.py` | 先读月度解；默认不重解。`--apply` 才再调用 `engine.solved` |
