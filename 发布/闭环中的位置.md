# 本仓库在产量成本控制闭环中的位置

数字都是示例，配置包 `TZ-cfg-2026.10-示例`。这一页说明本仓库是什么、不是什么。完整闭环的规划不在这个仓库里。

## 一句话

经营议题是：需求波动时，产量安排和转换成本能否在同一口径下算清、看见偏差，并留下可跟踪的决策。

完整闭环是三层能力，不是三个并列产品：

```mermaid
flowchart LR
  see["看见偏差\nControl Tower"] --> calc["算清方案\nVCS 引擎 ← 本仓库"]
  calc --> decide["建议与留痕\n多 Agent"]
  decide --> see
```

本仓库只做中间这一层：**产量成本测算引擎**。配置包冻住参数，求解器给出可复现的班次与科目差额，决策卡写明能不能用。

## 本仓库做什么

| 做 | 不做 |
| :-- | :-- |
| 月度选档：每个车间每个月一个 JPH × 班次 | 不替代 MES / APS 的下达与派工 |
| 场景旋钮与三种策略，同一套口径 | 不在看板进程里嵌求解器 |
| `plant_check` 就绪度 L0–L3 | 不自动改排产、开停线或人数 |
| 决策卡 + 结果快照（场景 ID、版本、哈希、间隙） | 不把模拟差额写成已实现节省 |
| 按天核对、空的实际排法表只计价 | 不建设多 Agent 与 Control Tower |

价值前提：现场有可调整的杠杆。没有收入和物料全成本时，不能据此判断工厂盈亏。

## 现在停在哪

| 能力 | 状态 |
| :-- | :-- |
| 引擎可算、可解释 | 已有。示例包 L2 |
| 结果可复现 | 种子、线程、间隙、下界已写入 |
| 结果契约 | 见 [样例/结果契约.md](样例/结果契约.md)。工作台每次写出 `.md` 决策卡和同名 `.json` 快照 |
| 与看板 / Agent 对接 | 契约已写明字段。本仓库不启 HTTP 服务 |
| 真实配置包对账 | 缺 `actual.csv` 与已结账月排法 |

下一级证据仍是：填真实排法做回放、Excel 科目对账、采纳日志实填。不靠再加细成本项推进。
