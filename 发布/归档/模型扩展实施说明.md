## 2. 两个必须修正的建模问题（实施中发现）

### 2.1 物料进目标 → 模型选择"停产"

**现象**：把物料（7.6–8.8 万/台）放进目标函数后，求解结果变成**产量 0、缺口 12 万台**——因为单台物料成本（≈8 万）远高于缺口惩罚（3 万），"不造更便宜"。

**根因**：这是**口径混用**。物料是每台车的变动成本，但模型没有收入项，于是"成本最小"退化为"什么都不做"。

**正确做法**（已实现）：物料**只做口径统计**（报表 `物料` 科目、单车成本），**不进目标函数**；决策用**边际贡献**：

```
目标：min 总成本(不含物料) − Σ margin[m] × 交付量[m,t] + 缺口惩罚×缺口
其中 margin = 售价 − 物料 − 变动物流  （⚠ 财务口径，月度发布）
```

配置 `margin.csv` 后即用此口径；未配置则退回原口径（`缺口惩罚×缺口`）。**这正是原盘点里"拓展 4：从成本到利润"的必要性证明**。

### 2.2 发运上限必须配套"成品库 + 发货量"

**现象**：只给发运上限、不允许成品库存时，模型被迫"边造边发"，发运上限低于需求就直接变成缺口，无法体现"先建库、旺季发货"的真实做法。

**正确做法**（已实现）：配置 `shipping_cap.csv` 或成品持有时，自动启用：
```
成品库平衡：fginv[m,t−1] + 产量[总装,m,t] = 发货[m,t] + fginv[m,t]
需求：      发货[m,t] + 缺口[m,t] ≥ 需求[m,t]
配额：      发货[m,t] ≤ 需求[m,t]     ← 防止"超配额交付"被边际贡献买成利润
发运能力：  发货[m,t] ≤ ship_cap[m,t]
```

**验证到的真实结论**：示例中旺季（10–12 月）逐月需求超过发运上限，**逐月**缺口合计恰好 1,470 台（=Σ(需求−上限) 正值月份）——即"发运能力成为瓶颈"，不是求解问题。放宽上限 ×1.5 后缺口归零、产量回到 12 万台。这条结论本身就是 R11（空间与网络）的价值：**瓶颈可能不在产线，在物流**。

## 7. 一句话总结

- **关系类方面**：R7/R8/R10/R11/R12 从"纸面"变成了"可跑的约束与科目"；R9/R13 靠口径表与决策单模板落地；R14 以单车碳成本近似。
- **费用因素方面**：物料、福利、间接人工、折旧、模具、物流、库存资金、保修、碳全部进报表，**单车口径从 3,579 元升到 87,034 元**（示例），口径差 100% 可解释。
- **最重要的两个发现**：① 物料进目标必须配边际贡献，否则模型会"停产"；② 发运上限必须配成品库，否则瓶颈会被误判成产能问题——**这两条都是"模型自洽 ≠ 模型可用"的真实例子**。
