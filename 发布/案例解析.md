# 案例解析

数字都是示例，配置包 `TZ-cfg-2026.10-示例`，不是工厂实绩。这一篇用已经解出的结果，把「问一个问题 → 改哪个旋钮 → 班次怎么变 → 钱为什么变 → 哪些话不能对外说」走完。

复现命令都在 `v5.2/` 目录下执行。网页是 `streamlit run workbench/app.py`，打开后用「选场景」或「对话」。

两套表的取整差 2 万元，读的时候分开：

| 出处 | 基准 | 口径 |
| :-- | --: | :-- |
| `output/results_summary.md`（`run.py`） | 总成本 44,287 万元，单车 3,691 元 | 目标值四舍五入到万元 |
| 工作台决策卡 | 运营成本 44,289 万元 | 运营成本 = 目标 − 流失惩罚 + 边际贡献。这套示例没有边际贡献、基准没有流失，和总成本只差在取整 |

下面旺季和电价用决策卡上的运营成本。五个标准场景的对照表用 `run.py` 的总成本。

---

## 1. 读卡之前

每个车间每个月只选一个档，固定费用不跟班次消失。这两句和 10 月的四档，写在 [设计说明](设计说明.md) 第 1–3 节。这一篇从一张已经解出的决策卡接着看。

---

## 2. 案例：9–12 月需求涨 15%

### 2.1 问题

计划问：旺季四个月订单比基准高 15%，全年还交得上吗，要不要改班次，多花多少。

预置场景名叫「旺季冲量」。旋钮只动需求：

```json
{"demand_month": {"9": 1.15, "10": 1.15, "11": 1.15, "12": 1.15}}
```

工资、电价、气价、加班上限、JPH 档位表、定员都没改。1–8 月的需求也没改。

决策卡：`output/workbench/2026-10-21_0026_旺季冲量.md`。求解状态 Optimal。

### 2.2 结果

| | 基准 | 旺季冲量 | 差额 |
| :-- | --: | --: | --: |
| 运营成本 | 44,289 万元 | 46,186 万元 | +1,897 万元（+4.28%） |
| 单车 | 3,691 元（`run.py` 总成本口径） | 3,650 元 | 约 −41 元 |
| 产量 | 120,000 台 | 126,525 台 | +6,525 台 |
| 延期 | 0 台·月 | 0 | 0 |
| 流失 | 0 台 | 0 | 0 |

多出来的 6,525 台就是这四个月的 15%。示例需求 9–12 月是 10,500、11,000、11,000、11,000，合计 43,500 台，43,500 × 0.15 = 6,525。延期和流失都是 0，多出来的订单全部交了。

1,897 万元 / 6,525 台 ≈ 2,907 元/台。这个边际成本低于基准单车 3,691 元，所以单车降到 3,650 元。降下来的是摊薄，不是单台变便宜了。

### 2.3 班次对照

基准（`run.py` 的 `results_summary.md`，与决策卡叙述一致）：

| 车间 | 基准 | 旺季冲量 | 怎么读 |
| :-- | :-- | :-- | :-- |
| 冲压 | 多数月份 50 JPH × 1 班，只有 10 月两班 | 1–8 月仍是 1 班，9–12 月都开两班 | 旺季四个月把冲压从一班拉到两班 |
| 焊装 | 2 月、8 月降到 36 JPH × 1 班，其余 36 × 2 | 与基准相同，包括 2 月和 8 月的一班 | 焊装没有为这 15% 再加一班 |
| 涂装 | 只有 5 月和 10 月是 36 JPH × 3 班 | 5 月仍是三班，另外 9–12 月整段开成三班 | 旺季的瓶颈表现在涂装加班次 |
| 总装 | 全年 36 JPH × 2 班 | 全年仍是 36 JPH × 2 班 | 总装档位和班次都没变 |

所以这句话可以对外说：这 15% 交得上，总装不用改，冲压旺季改两班，涂装旺季改三班。

这句话不能说：总装有富余所以全厂都不忙。涂装已经加到三班，焊装在淡月仍会降到一班，车间之间不是同步加档。

### 2.4 钱差在哪三个科目

决策卡给出差额最大的三项：

| 科目 | 相对基准 |
| :-- | --: |
| 人工 | +619 万元 |
| OH | +600 万元 |
| 加班 | +463 万元 |

三项合计 1,682 万元，净增成本是 1,897 万元。差额 215 万元散在其余科目里，卡片只列出绝对值最大的三项。

人工和加班上升，是因为多做了 6,525 台，并且冲压、涂装在旺季多开了班。OH 上升要和「多开班的人工」分开：产量上去之后，随产量走的制造费用会增加；不随班次消失的固定部分，不会因为少开一个月的班就从全年里扣掉。

### 2.5 这张卡没有回答的事

- 没有做 40 个需求样本，没有 P90，没有超预算概率。卡片第④栏写的就是这件事。
- 月度借调仍按人·天凑平。按天核对焊装和涂装是不是同一天开工之前，借调净额不要写成已经省下的钱。
- 派遣加临时工占比示例是 20%。法规派遣上限是用工总量的 10%，20% 只能当成派遣加临时工，等 HR 定口径。

## 3. 对照案例：电价涨两成，产量不变

问题：电价系数 ×1.2，其他不动。决策卡 `output/workbench/2026-10-21_0024_例题 2 · 电价上浮两成.md`。状态 Optimal。

| | 基准 | 电价 ×1.2 | 差额 |
| :-- | --: | --: | --: |
| 运营成本 | 44,289 万元 | 45,056 万元 | +767 万元（+1.73%） |
| 单车 | | 3,755 元 | 产量仍是 12 万台，单车上升是电更贵 |
| 产量 / 延期 / 流失 | 120,000 / 0 / 0 | 120,000 / 0 / 0 | 交付不变 |

班次：

- 总装仍是全年 36 JPH × 2 班。
- 冲压与基准相同：10 月两班，其余一班。
- 焊装从「2 月、8 月一班，其余 36 × 2」改成全年 30 JPH × 2 班。
- 涂装在基准的 5 月三班之外，10–12 月也开了三班。

科目差额最大的是：能源-电(运行) +439 万，能源变动 +315 万，加班 +207 万。电价本身在涨，所以能源科目上升是直接原因。班次有调整，但总装没改，说明这套示例里靠调总装班次躲不开这笔电费。焊装降档、涂装部分月份加三班，是求解器在新电价下另选的一个最优组合，不要把它读成「涨电价就该给涂装加三班」的规定。

`run.py` 里同名场景「电价+20%」的总成本是 45,060 万元、能源 6,343 万元（见 `results_summary.md`）。和工作台的 45,056 万元差 4 万，两边都是 Optimal，差在取整和求解间隙里。对外引用时写明是哪一次运行、哪一列（总成本还是运营成本）。

能源参数仍是行业暂定，卡片挂了假设 A11。负责人确认电价、气价、启停之前，767 万元只说明示例参数下的相对变化。

## 4. 五个标准场景放在一张表里

来源：`output/results_summary.md`，`python3 run.py`。状态都是 Optimal。成本是总成本（万元）。

| 场景 | 总成本 | 产量 | 单车（元） | 加班 | 能源 | 总装 |
| :-- | --: | --: | --: | --: | --: | :-- |
| 基准 | 44,287 | 120,000 | 3,691 | 702 | 5,509 | 全年 36×2 |
| 需求 +10% | 47,399 | 132,000 | 3,591 | 931 | 5,839 | 仍是全年 36×2 |
| 需求 −10% | 41,155 | 108,000 | 3,811 | 668 | 5,057 | 全年改为 30×2 |
| 电价 +20% | 45,060 | 120,000 | 3,755 | 661 | 6,343 | 仍是全年 36×2 |
| 工资 +5% | 45,127 | 120,000 | 3,761 | 693 | 5,510 | 仍是全年 36×2 |

怎么读每一行：

- **需求 +10%**（全年每个月都乘 1.1，和旺季「只乘 9–12 月」不是同一个旋钮）。产量 13.2 万台，缺口 0。单车降到 3,591 元，仍是摊薄。总装不改档。涂装有多个月开到三班，焊装不再出现一班月份。人工和能源一起上升，因为多做了 1.2 万台。
- **需求 −10%**。焊装和总装全年从 36 JPH 降到 30 JPH × 两班，没有丢单。单车升到 3,811 元，人没有按产量同比例减掉。能源只从 5,509 万降到 5,057 万，降幅小于 10%：节拍变低以后，烘房按小时烧，单台用气不会按台数同比例下降。
- **电价 +20%、工资 +5%**。产量和总装班次都保持基准。多出来的钱主要在能源或人工，不是在「少交了车」。

`golden.csv` 里需求 −10% 的旧基线是 40,966 万元。这次 `run.py` 在 120 秒时限下停在 41,155 万元，仍打印 Optimal。差约 189 万元时，先看时限和间隙，再查有没有人改过公式。

## 5. 策略卡和场景卡不是同一件事

场景卡回答「外部条件变了，基准算法怎么接」。策略卡回答「条件不变，额外加上人力或稳定性约束要多付多少」。

`output/strategy_summary.csv`（示例，总成本万元）：

| 策略 | 总成本 | 比成本优先 | 人数最大月波动 | 延期（台·月） | 在说什么 |
| :-- | --: | --: | --: | --: | :-- |
| 成本优先 | 44,288 | — | 100% | 0 | 最便宜。人数可以逐月大起大落，招聘和培训没有单独计价 |
| 保人力（月变化 ≤5%） | 44,306 | +18 | 0% | 0 | 人头稳住，多用加班。这套示例里几乎不用多花钱 |
| 稳定优先 | 44,746 | +458 | 0% | 524 | 少跳档、少加班，换来 524 台·月晚交 |

策略扫描里的「成本优先」44,288 万元，和 `run.py` 基准 44,287 万元、工作台基准 44,289 万元，是三次取整，不是三套业务口径。策略卡如果写「比成本优先多付多少」，页眉必须写扫描口径，不要和旺季卡上「比基准多 1,897 万」加在一起。

稳定优先多付的 458 万元，买的是人数不跳和少加班，同时接受延期。它没有多生产汽车。

## 6. 自己走一遍

1. 打开网页的「选场景」，运行「旺季冲量」。卡片上的运营成本应为 46,186 万元，总装全年 36 JPH × 2 班。缓存命中时几秒内出来。
2. 或在「对话」输入：`9到12月需求涨15%，成本会涨多少？` 页面应复述预置场景「旺季冲量」，点确认之后才求解。
3. 再跑「电价涨两成」。产量应仍是 120,000，总装班次不变，能源科目上升。
4. 打开「参数来源」，确认电价、工资、需求各自由谁负责。表是只读的。
5. 命令行同一张卡：`.venv/bin/python -m workbench.api --scenario 旺季冲量`

正式 CSV 不会被网页改写。要改工资或需求表，按 [修改流程说明](修改流程说明.md)，先复制配置包，不要运行 `gen_data.py`。
