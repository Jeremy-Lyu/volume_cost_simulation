# 13 v5–v5.2 新增：决策层、能源细化、按天排产、人工弹性与换档成本

> 本章对应模拟器 v5（决策层）、v5.1（分时电价、天然气、启停炉、需量电费、按天排产）和 v5.2（按天人工弹性、跨车间借调、JPH 换档成本）。代码在 `v5.2/`。工厂改基数、策略或公式的步骤见仓库 `发布/工厂改数与重算指南.md`。**全部数字为示例数据**；标 ⚠ 的参数为行业假设，汇总在 `data/假设登记表.csv` 和附录 C。

## 13.1 v5 决策层：从"一个最优解"到"可选方案 + 风险"

- **定义**：月度 MIP 只给出一个成本最低方案；决策层在此之上生成多个可比较方案，评估其风险，给出推荐和理由。
- **组成与公式**：
```
加权目标 = 运营成本 + w_稳定 × 人数月波动惩罚 + w_交付 × 延期台月惩罚 + ...（strategy_v5.py，17 组权重扫描）
帕累托前沿 = 不存在"成本更低且波动、延期都不更差"的方案集合
推荐 = 帕累托前沿中满足阈值（⚠ 示例：人数波动 ≤ 30%、延期 ≤ 800 台·月、无流失、成本 ≤ 成本优先 + 5%）且成本最低者
预测：P10 / P50 / P90 需求（forecast.py）；蒙特卡洛：P(成本超预算)、P(有缺口)（risk.py）
稳健优化：同一 y 方案在 8 个需求情景下的期望/最坏成本最小（robust.py）
影子价格：固定 y 后放宽一项资源 1 单位，成本下降多少（outputs_v5.shadow_prices，有限差分）
```
- **口径注意**：
  1. 决策单、成本瀑布、结论文字必须用**同一个基准**（扫描口径的"成本优先"）；`outputs_v5.check_baseline()` 生成前自检（v5.1 修复）。
  2. 扫描口径用 gap 0.2%、时限 40 s，与精解（gap 0.01%）可能差几万元，比较方案时只在同一口径内比。
  3. 影子价格只对小幅放宽有效；放宽幅度大了排程会变，要重解 MIP（有限差分）。
- **示例（示例数据，v5.2 全流程 `run_v5.py`）**：月度基准（精解）全年总成本 **44,288 万元**（v5.1 为 44,746 万元，v5 为 43,433 万元；差异来自 v5.1 的能源口径与 v5.2 的人工弹性/换档成本）。成本优先 44,297 万元（扫描口径），推荐「稳定2·交付3」44,306 万元（+9 万），人数最大月波动 100% → 0%，延期 0 台·月。v5.1 时推荐方案要多花 150 万元才能把波动从 72% 降到 16%；v5.2 因换档成本已抑制频繁换档，稳定方案几乎不用多花钱。
- **代码**：`run_v5.py`、`strategy_v5.py`、`forecast.py`、`risk.py`、`robust.py`、`outputs_v5.py`（`waterfall`、`decision_sheet`、`check_baseline`、`shadow_prices`）。

## 13.2 分时电价（TOU）与班次加权电价

- **定义**：按小时分尖峰/高峰/平段/低谷计价。v5.1 内置浙江两版：浙发改价格〔2026〕112号（2026-07-01 起，高峰 16–23 点）与浙发改价格〔2024〕21号（白天高峰，可做历史回测）。
- **公式**：
```
小时电价 p(h, t) = tou_price[版本, 季节(t), 时段(h)] × 电压/购电系数
班次 k 的加权电价 = Σ_{该 k 班覆盖的小时 h} p(h,t) ÷ 小时数        （班次时刻见 shift_times.csv）
加班电价 = 加班所在时段（默认休息日 8–16 点）的平均电价
运行电费 = run_kw × 开动小时 × 班次加权电价；单车变动电费 = kwh_per_unit × 产量 × 班次加权电价
```
- **示例（示例数据，10 月，110kV 代理购电，2026 版）**：早班 8–16 点 = 5 h 平段 0.5813 + 3 h 低谷 0.2961 → **0.4743**；1+2 班平均 **0.7046**（中班 16–24 点 7 h 高峰 0.9854 + 1 h 平段）；1+2+3 班平均 **0.5803**。结论：新政下**中班最贵、夜班最便宜**，与 2024 版相反；旧手册 §6.4 中"白班=中班=0.90"的假设示例已不适用。
- **口径注意**：电压（110kV/10kV）、购电方式（代理/市场）、季节月份映射都会改单价 ⚠（`energy_config.json`）。
- **代码**：`energy.py: hour_prices / shift_price / ot_price / day_price`；`cost_functions.price(d,t,k)`；数据 `tou_periods.csv`、`tou_price.csv`、`shift_times.csv`。

## 13.3 天然气：按小时为主、按台为辅

- **定义**：涂装烘房车身在炉时间由工艺定死，燃气主要用于维持炉温和送排风（按开炉小时），只有一小部分是车身吸热（按台）。
- **公式**：
```
运行用气 = gas_run_m3h × 开动小时 + gas_m3_per_unit × 产量
单车用气 = gas_run_m3h ÷ (JPH × 按天产能折算系数) + gas_m3_per_unit
保温用气 = gas_run_m3h × gas_standby_ratio × 保温小时；电泳槽保温 = ecoat_hold_m3h × 停炉小时
燃气费 = 用气量 × 气价（energy_config.json: gas_price）
```
- **示例（示例数据，⚠ gas_run_m3h = 450、gas_m3_per_unit = 4、气价 3.6 元/m³、按天产能折算系数 0.9）**：JPH30：450 ÷ 27 + 4 = 20.7 m³/台 → 74.5 元/台；JPH36：450 ÷ 32.4 + 4 = 17.9 m³/台 → 64.4 元/台。**JPH 越高，单车分摊的烘房气越少**。
- **代码**：`energy.gas / parts / estimate_per_unit`；`cost_functions.var_gas`；`shop_energy.csv`。

## 13.4 启停炉与保温：临界间隔

- **定义**：停线间隔内可以"保温待机"（不熄火）或"停炉"（再开要升温）。间隔越长越值得停炉。
- **公式**：
```
保温每小时 = standby_kw_ratio × run_kw × p + gas_run_m3h × gas_standby_ratio × 气价
停炉每小时 = (off_kw_ratio × run_kw + ecoat_hold_kw) × p + ecoat_hold_m3h × 气价
启炉一次 = heatup_kwh × 升温时段电价 + heatup_m3 × 气价
临界间隔 h* = 启炉一次 ÷ (保温每小时 − 停炉每小时)；间隔 > h* 就停炉
```
- **示例（示例数据，涂装 JPH24 档 3,500 kW，10 月，⚠ 参数见 shop_energy.csv）**：保温 ≈ 1,257 元/h，停炉 ≈ 333 元/h，启炉一次 = 4,500 kWh × 0.4387 + 900 m³ × 3.6 ≈ **5,214 元** → 临界间隔 **约 5.6 h**。周末 48 h 远大于 h* → 自动停炉；两班制夜间 8 h 也大于 h*，但默认 `night_policy = hold`（保温）⚠ 待工艺确认（频繁冷启动影响质量，见 13.10 复产质量）。
- **代码**：`energy.hold_cost_h / off_cost_h / startup_cost / breakeven_hours / _gap`。

## 13.5 需量电费（两部制）

- **公式**：需量电费 = 同时率 × Σ 运行功率（月最大）× 需量电价；示例 ⚠：同时率 0.85、40.8 元/kW·月。
- **口径注意**：按需量还是按容量计费需与能源部门确认 ⚠；按天模型里需量是"全月最大一天"，因此"开几天停几天"不省需量电费，反而集中开工可能抬高峰值。
- **代码**：`energy.parts`（月度）、`daily.py: peak`（按天）。

## 13.6 按天排产：焊装 → 白车身缓存 → 涂装 → PBS

- **定义**：在一个月内逐日决定每个车间开不开、开几班、停炉还是保温，并跟踪白车身缓存和 PBS 库存。
- **公式（核心约束）**：
```
B_j = B_{j-1} + q_BIW,j − q_PNT,j，      biw_buffer_min ≤ B_j ≤ biw_buffer_max（白车身库容）
PB_j = PB_{j-1} + q_PNT,j + 缺货_j − 总装需求_j，0 ≤ PB_j ≤ pbs_buffer_max
q_s,j ≤ Σ_{i,k} 日产能(i,k) × y_s,j,i,k；Σ y ≤ 1（每天最多一种 JPH×班次）
启炉_s,j ≥ 停炉_{j-1} − 停炉_j；月末缓存 ≥ 月初
成本 = 人工 + 休息日加班 + 班车外包 + 运行电/待机电/天然气 + 启停 + 需量 + 缓存持有（存储 + 资金占用）+ 缺货惩罚
```
- **策略对照**：连续生产（工作日三班）、同步开停、模型自主、两班 + 周末停炉、v5.2 新增"每个工作日都开（不主动停线）"。
- **影子价格**：固定所有二进制变量后解 LP，读 `bufmax_j` 约束对偶值之和 = 库容 +1 台（全月）能省多少；>0 才说明库容在"卡住"。
- **代码**：`daily.py: build / solve / shadow_fd / demand_sweep / dispatch_sweep`；`daily_flex_sweep.py`；参数 `daily_config.json`。

## 13.7 按天人工弹性（v5.2）

- **定义**：停工日能省多少人工，取决于派遣/临时工占比和停工日发薪比例。
- **公式**：
```
可省比例 φ = (1 − 派遣比) × (1 − 正式工停工日发薪%) + 派遣比 × (1 − 派遣停工日发薪%)
月人工（按天模型）= 定员班次人数 × 月工资 × (1 − φ)  +  Σ_开工的工作日 当天上班人数 × 月工资 ÷ 计薪天数 × φ
停 1 个工作日省（月度模型）= 定员班次人数 × 月工资 × 福利系数 ÷ 计薪天数 × φ + 夜班补贴/天 + (开工日能源 − 停机日能源)
月度模型新增变量 sd[s,i,k,t] = 停工日数（≤ 工作日 − 1），产能扣 sd × 日产能
```
- **示例（示例数据，⚠ 默认派遣 20%、正式工停工日 70%、派遣 0%、计薪 21.75 天）**：φ = 0.8 × 0.3 + 0.2 × 1 = **0.44**。焊装 JPH36 两班 255 人/班 × 2 = 510 人，月薪 9,000：510 × 9,000 ÷ 21.75 × 0.44 = 92,855 元 + 夜班补贴 255 × 30 = 7,650 元 → 停 1 天省人工 **100,505 元**；能源再省约 2.2 万元。涂装 JPH36 两班停 1 天：人工 48,085 元、能源 68,766 元（涂装能源占比高）。派遣比 50% 时 φ = 0.65。
- **口径注意**：
  1. 停工日发薪比例须符合当地停工停产工资规定 ⚠（HR/法务确认）。
  2. "停整天"与"每天少开一班"在本口径下省的人工相同；两者差在能源（停整天省待机/保温，但多一次启炉）和库存。
- **代码**：`data/labor_flex.csv`；`cost_functions.flex_var_share / stop_day_saving / cap_per_day`；`model_builder.py`（`sdo`）；`daily.py`（`fvs`）。

## 13.8 跨车间借调（v5.2）

- **定义**：一个车间停工/少开班的人，可以去支援另一车间，借入方可少雇人，上限为本车间人数的 borrow_limit（⚠ 默认 10%）。
- **公式**：
```
借入人数 bw[s] ≤ borrow_limit × 车间人数
月度：Σ_s bw[s,t] × 工作日 ≤ Σ 借出方停工日空闲人·天；节省 = bw × 月薪，增加 = bw × 工作日 × 日薪 × φ（借出方这些天不能按停工省）
按天：借入方每个开工日用 u[s,j] ≥ bw[s] − M(1 − 开工)，u[s,j] ≤ 另一车间当天空闲人数（逐日核对）
```
- **口径注意 ⚠**：月度模型按"人·天总量"平衡，不核对是否同一天有空闲人，**偏乐观**；按天模型逐日核对，焊装与涂装基本同日开工，借调为 0。技能匹配、培训、安全上岗资格未建。
- **示例（示例数据，v5.2 月度基准）**：借调节省人工 1,437 万元/年，借出方占用 +604 万元，净 −833 万元，是 v5.2 月度成本下降的最大来源，需在按天层和业务上核实后再使用。
- **代码**：`model_builder.py`（`bw`、`bwsrc_t`）、`daily.py`（`bw_s`、`u_s_j`）。

## 13.9 JPH 换档成本（v5.2）

- **定义**：车间相邻两月换 JPH 档需重新做线平衡、工位验证、人员调整，并损失若干天产出。
- **公式**：
```
z[s,i,t] = Σ_{k>0} y[s,i,k,t]（t 月是否用 i 档）
换档 sw[s,i,t] ≥ z[s,i,t] − z[s,i,t−1]；成本 = cost_per_switch × Σ sw
损失产出 lost[s,t] ≥ lost_days × 日产能(i,k) × (y[s,i,k,t] − z[s,i,t−1])，从当月产能中扣除
```
- **示例（示例数据，⚠ 30 万元/次 + 2 天）**：焊装 9 月从 JPH30 换到 JPH36 两班：日产能 36 × 7.5 × 2 = 540 台 → 损失 1,080 台产能 + 30 万元。v5.2 基准全年换档 **1 次**（v5.1 为 18 次：STP 4、BIW 4、PNT 4、TCF 6）。
- **口径注意**：从 0 班恢复到某档也算一次换档（含复产准备）⚠；第一个月不计（无上月数据，按天模型可用 `prev_jph_tier` 指定上月档）。
- **代码**：`data/jph_switch.csv`；`cost_functions.jph_switch`；`model_builder.py`（`jsw`、`jlost`）；`daily.py`（`prev_jph_tier`）。

## 13.10 尚未建模、已登记的事项

| 事项 | 影响方向 | 建议处理 |
|:--|:--|:--|
| 招聘与培训提前期 | 升档/扩班当月即可实现 → 偏乐观 | 加"提前 1–3 个月决策"约束 ⚠ |
