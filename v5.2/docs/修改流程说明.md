# 修改流程说明（v5.2）

完整步骤、字段和读结果时要核对的点在 [工厂改数与重算指南](../../DOC/工厂改数与重算指南.md)。这里只留动手时要看的短表。命令都在 `v5.2/` 下执行。数字是示例。

不要运行 `gen_data.py`，它会覆盖已填写的表，并写成更早的列。

## 1. 只改基数 → 改 CSV/JSON，再重算

| 想改什么 | 文件 |
| :-- | :-- |
| 需求、工作日、车型月上限 | `demand.csv`、`calendar.csv`、`capacity_limit.csv` |
| JPH 档、每班定员、运行功率 | `jph_options.csv`（定员须随 JPH 不下降） |
| 班次小时、夜班个数、班车、外包 | `shift_options.csv` 的 `night_shifts`。夜班金额在 `global_params.csv` 的 `night_allowance_per_head_night` |
| 工资、标准月工时、加班倍数、加班绝对上限、流失惩罚、延期成本、求解秒数 | `global_params.csv`。加班单价由月薪 / `std_hours_month` × `ot_multiplier` 派生，表里的 `ot_rate_per_head_hour` 不生效 |
| 车间 OH、加班常规上限、缓存、停线月固定 | `shop_params.csv` |
| 派遣比、停工日发薪、借调上限、计薪天数 | `labor_flex.csv` |
| 换档费用和损失天数 | `jph_switch.csv` |
| 分时电价、电压、气价、需量 | `energy_config.json`、`tou_price.csv`、`tou_periods.csv` |
| 班次时刻、车间气和启炉、周末停炉 | `shift_times.csv`、`shop_energy.csv` |
| 按天库容、当月台数、是否允许借调 | `daily_config.json` |
| 招聘月增幅、换档后效率、维修天数、加急费、复产损失 | `coarse_params.csv`。默认不改变现成本。示例值在场景「开停校正」 |
| 尚未确认的假设 | `data/假设登记表.md`。A12 的 2%–3% 是回测门槛，还没有结果 |

```bash
python3 plant_check.py
python3 run_quick.py                              # 基准；改了哪张表就重算哪一层
python3 run_quick.py --scenario 旺季冲量
python3 run_quick.py --scenario '{"wage": 1.05}'  # 不改表，只乘一次
python3 run_quick.py --part all --force           # 忽略缓存
```

要和五个标准场景、`golden.csv` 对齐时再跑 `python3 run.py`（时限 120 秒时要数分钟）。本厂配置包：先复制 `data/` 到 `plants/本厂代号/`，改 `plant.json` 的版本，再 `python3 run_plant.py plants/本厂代号`。

## 2. 改策略

| 想改什么 | 改哪里 | 重算 |
| :-- | :-- | :-- |
| 增加一种冲击（需求、停线、电价、禁三班、加班上限、派遣比等） | `data/scenario_library.csv` 的 `knobs`，旋钮见 `scenarios.py` 文件头 | `run_quick.py --scenario 名称` 或 `stress_test.py` |
| 成本优先 / 稳定优先 / 保人力 的约束（人数月变化、JPH 每月一档、班次按季、利用率） | `strategies.py` 的 `STRAT` | `python3 strategies.py` |
| 一批拍板问题；订单减半到翻倍 | `factory_analysis.py` 的 `catalog()`；开关在 `data/switches.csv` 的 `extreme` | `python3 factory_analysis.py` 或加 `--extreme` |
| 加权扫描的推荐阈值 | `strategy_v5.py` 的 `THRESH`、`GRID` | `python3 run_v5.py`（慢，改一张表不必跑） |
| 按天开哪几天 | `daily_config.json` | `run_quick.py`（只动这个文件时只重算按天） |

`head_change`、`jph_step`、`shift_quarter`、`util_cap` 目前不能写进场景库 JSON。

## 3. 改一条计算公式

1. 只改对应函数：产能和加班单价在 `cost_functions.py`，月度选择在 `model_builder.py`，电价在 `energy.py`，按天在 `daily.py`，科目在 `report.py`。
2. 在 `tests/` 加一条手算对照。
3. `python3 -m pytest tests/test_v52.py tests/test_v4_rules.py tests/test_units.py -q`，再 `python3 run.py`。
4. 确认新结果是想要的口径之后，才 `python3 golden.py --update`，并在 `CHANGELOG.md` 写原因和差额。
