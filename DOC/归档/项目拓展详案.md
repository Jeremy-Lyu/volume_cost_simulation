## 0. 总纲：三条线、四阶段、评审门

```
A线 数据底座： 拓展1(真实数据+对账) → 拓展8(平台化) → 拓展9(W1落地)
B线 模型深化： 拓展3(JPH精细) → 拓展6(全成本) → 拓展5(稳健日常化) → 拓展2(分层计划)
C线 智能决策： 拓展7(LLM+Laya) → 拓展10(运营闭环)
```

| 阶段 | 时间 | 内容 | 评审门（业务 go/no-go） |
|---|---|---|---|
| 阶段0 诊断 | 2 周 | 12 问 + 参数认领 + 灯塔厂初筛 | 痛点清单确认、试点范围锁定 |
| 阶段1 试点 | 4–6 周 | 拓展1（必做） | 首份偏差报告财务签认、过期参数=0 |
| 阶段2 深化 | 一季度 | 拓展3/5/6/7/8 + W1 启动 | 回测偏差收窄、解释器上线、平台压测通过 |
| 阶段3 推广 | 按波次 | 拓展2/9/10 | W1 验收、KPI 达标、转常态运营 |

原则：每阶段只承诺一个"看得见的结果"；阈值先跑三月再定；通用进核心、特有进配置，禁私改核心。

## 拓展 1：从示例数据到真实数据——参数映射与首次对账（最高优先级）

### 1.1 现状与证据

- `data/*.csv` 9 表全齐；`plant_check` 27 项全 PASS；TZ 就绪度 **L2**（可测算、缺 `actual.csv`），DEMO_B **L3**（含 `actual.csv`，故意埋涂装 8 月 −15.5% 演示追溯）。
- `run_plant.py` 已具备"检查→求解→回测"链路；`validate()` 断言日历/上限/JPH 齐全。
- 基准结果：总成本 42953 万/年、12 万台、单车 3579 元（模型口径），`scenario_summary.csv` 5 场景全 Optimal。

### 1.2 核心问题

真实工时/定员/单价/上限/日历**无人认领、无版本、无来源**；测算从未与 MES/财务对过账——模型准不准没人知道，这是信任地基。

### 1.3 总体思路

先认领（谁产生谁负责）→ 再入表（搬进数仓带版本）→ 后对账（回测 3–6 个月，超阈追因修参数）。**不改模型逻辑**，只换数据源。

### 1.4 详细设计

**1.4.1 参数认领表**（⚠ 阶段0确认）：

| 参数 | 来源系统 | 负责人 | 更新频率 | 原型表 |
|---|---|---|---|---|
| 工时/JPH档/定员/功率 | PLM/工艺文件、IE 测算 | IE | 事件（ECN/线平衡） | `jph_options.csv` |
| 产能上限/日历/需求 | 计划、S&OP | 计划/排产 | 月/季/事件 | `capacity_limit/demand/calendar` |
| 工资/加班/补贴/上限 | HR、工会协议 | HR | 年/政策 | `global_params/shift_options` |
| 电价/单车能耗 | 能源计量、电价通知 | 能源/设施 | 季/调价 | `global_params/shop_params` |
| OH/班车/外包/科目口径 | 财务、行政/采购合同 | 财务 | 年/合同 | `shop_params/shift_options` |
| 缓存容量/持有 | 生产+物流 | 物流/生产 | 事件 | `shop_params` |

**1.4.2 三类参数先行**（试点范围，控制 4–6 周）：VCS 产能限制配置 + 工资/加班 + 能源。数仓表结构与 CSV 同构，加五字段：`版本号、生效日、失效日、负责人、来源`。

**1.4.3 字段映射表**（每类源系统一张）：

```
源系统.字段 → 标准字段 │ 转换规则 │ 确认人 │ 示例值
MES.dept_id → shop │ 映射表 │ key user │ BIW
HR.pay_code → wage_per_head_month │ 月折算 │ HR │ 9000
能源.meter_kwh → run_kw/kwh_per_unit │ 回归拆分 │ 能源 │ 见1.4.4
```

LLM 先给映射建议（置信度），key user 逐条确认，低置信重点看——从"从零写"变"审稿"。

**1.4.4 能耗拆分方法**（固定 vs 变动）：取 6–12 个月车间电表 + 产量 + 班次，做 `电量 = a×开动小时 + b×产量 + c` 回归：`a→run_kw`，`b→kwh_per_unit`。先线性基线，R² 不足再分段（烘房启停）。⚠ 需分车间电表；没有则先按功率清单分摊并标注可信度。

**1.4.5 对账流程**（`run_plant.py` 回测位已预留）：

```
取近3–6月实际参数 → 冻结快照重解 → 按车间×月×科目对比
→ 偏差超阈值(示例±5%⚠) → 追溯：人数差查定员/出勤，加班差查停线，能耗差查功率/单耗，人工差查工资/补贴
→ 修参数发新版 → 出偏差报告（财务签认）
```

**1.4.6 代码改动点**：`data_loader.load()` 加 `source="db"` 分支（SQL 读数仓，字段同名）；`plant_check` 加"过期参数数"检查；`run_plant` 加 `--months N` 回测窗口参数。核心求解零改动。

### 1.5 业务与组织动作

| 动作 | 主责 | AI&Data 交付 | 节奏 |
|---|---|---|---|
| 参数认领会 | 业务 Owner | 认领表、口径字典初稿 | 阶段0 第1周 |
| 数据访问审批 | IT + 数据部门 | 接入清单、脱敏方案（工资列） | 阶段0 第2周 |
| 搬表 + 映射确认 | 中心团队 + key user | 参数层表、映射表、质量规则 | 阶段1 前2周 |
| 首次对账会 | 计划（确认）+财务（签认） | 偏差报告、校准清单 | 阶段1 后2周 |

### 1.6 风险与应对

| 风险 | 应对 |
|---|---|
| 审批下不来 | 先用脱敏/汇总数据做试对账，并行走审批 |
| 无分车间电表 | 功率清单分摊 + 标注低可信度，列入二期计量改造需求 |
| 口径吵架（人数/单车） | 财务定成本口径、生产定产量口径，会上锁定，会下不翻 |
| 业务时间不够 | 对接人每两周半天写入 MBO ⚠ |

### 1.7 验收与 KPI

- 过期参数数 = 0；每个参数有负责人；试点参数不再依赖手工 Excel。
- 首份月度偏差报告经财务签认；超阈偏差 100% 有原因归类（参数错/口径异/模型未覆盖）。
- 过程 KPI：映射表确认率、质量规则通过率、手工导数次数（目标待定 ⚠）。

### 1.8 工作量与依赖

约 4–6 周，中心团队 1 数据 + 1 算法兼职，业务 key user 5–6 人兼职。无前置依赖，是所有拓展的前置。

## 拓展 2：从月度到周/日——分层计划

### 2.1 现状与证据

月度 MILP 联解（`y` 离散 + `ot/x/inv` 连续）；下层只有 0A 图 LOW 节点设想；`shift_quarter/jph_step` 是"少切换"的粗近似。压力测试证明缓存可跨月调（涂装 11→12 月 880 台经 PBS）。

### 2.2 核心问题

月方案落不了地（某技能缺 5 人、班车排不开、颜色批量不够）无处反馈；排序/换色/间隔规则在月层表达不了（要素拆解 §15/§2 均标注 ⚠ 未建）。

### 2.3 总体思路

月定档（JPH×班次×产量冻结为边界）→ 周排班组+排序 → 日排人点名。下层不可行**结构化回传**为月层新约束，重解。月周日三层只通过边界与反馈单交互，不互改内部逻辑。

### 2.4 详细设计

**2.4.1 层间接口**：

```
月→周：{车间,周,JPH档,班次,周产量(月产量/4.33),加班额度} + 缓存收发计划
周→日：{班组,日,车型序列,人数需求(分技能)}
日→周→月反馈单：{不可行类型, 车间, 时段, 缺口量, 建议约束}
```

**2.4.2 周模型（新增 `weekly.py`）**：决策：周产量 `xw[s,m,w]`、班组 `g`、排序 `seq`。约束：① 周产量和 = 月产量；② Car Sequencing：任意连续 N 台中高工时配置 ≤K 台（如天窗车 5 台中 ≤2）；③ 涂装换色批量 ≥B 台/色；④ 技能覆盖：每班每关键工位 ≥1 持证人。目标：换色次数 + 周间波动 + 加班最小。

**2.4.3 日模型（复用 HR 排班或新增 `daily.py`**）：点名：实到 vs 需求（分技能）；缺口→周内调班/借调/外包；仍缺→反馈单。

**2.4.4 反馈转约束对照表**：

| 下层问题 | 转月层约束 | 代码位置 |
|---|---|---|
| 某技能连续缺勤 | 该车间该月 `cap` 扣减 q% 或禁用某档 `y=0` | `build()` 加 `forbidden` 集 |
| 班车运力不够 | 该车间该月 `k≤2` | C12 扩展 |
| 颜色批量凑不够 | 该月该车型 `x` 下限/上限 | C4 加下限 |
| 供应商周内断料 | 该周产量上限 → 折月 `supply` | C6 |

**2.4.5 先行简化**（不等周模型上线）：月层加"可执行分"启发式——`util_cap` 按车间设、JPH 切换罚（目标加 `switch_cost×|Δy|`），把最糙的不可行先挡掉。

### 2.5 业务与组织动作

主责：计划/排产（周 Aligned with MPS），生产（班组执行），HR（技能/出勤）。AI&Data 交付周模型 + 排序规则配置页 + 反馈单流转。节奏：周滚动（每周四定下周），月冻结（每月 25 日锁下月）⚠。

### 2.6 风险与应对

| 风险 | 应对 |
|---|---|
| 排序数据（配置明细到台）拿不到 | 先做周产量+班组，排序二期；用配置比例近似 |
| 周模型求解慢（序列组合爆炸） | 启发式（贪心+局部搜）先行，MILP 只做小规模校验 |
| 月周两张皮 | 冻结边界 + 反馈单强制回传，周私自改月计划算违规 ⚠ |

### 2.7 验收与 KPI

月方案一次下达成功率（连续两月达标 ⚠）；不可行反馈单 100% 有约束转译；周产量达成率；换色次数趋势降。

### 2.8 工作量与依赖

约 1–2 季度，需懂排序算法 1 人。依赖拓展 1（真实定员/技能/上限）。

## 拓展 3：从离散三档到"档 + 微调"——JPH 精细化与组合折损

### 3.1 现状与证据

每车间 3 档（`jph_options.csv`）；TCF 10 月例显示离散跳变 147 万；`capacity()` 无组合折损、无爬坡（README 简化清单明示）。

### 3.2 核心问题

档内无级差→旺季组合复杂时系统性乐观（高工时车多但 JPH 不变）；新车前 3 月无爬坡→排产过满。

### 3.3 总体思路

短中期**系数法**（不动整数结构）：`有效JPH = 档JPH × combo_factor × ramp`；中长期**增档**（实测瓶颈工位后加档，如 TCF 33 档）。

### 3.4 详细设计

**3.4.1 组合折损**：新表 `combo_factor.csv`：`{shop, 高工时配置占比区间, factor}`，如 BIW 天窗率 >40% → 0.95。`capacity()` 末乘系数。占比来自块 3 配置比例。标定：用历史"复杂月"实际 JPH/档 JPH 反推，季度更新。

**3.4.2 爬坡**：新表 `ramp.csv`：`{shop, model, 上市后第n月, factor}`，如新车 1–3 月 0.7/0.85/0.95。`capacity()` 乘系数；`shortage_penalty` 爬坡期可下调（允缺口，保质量）⚠。

**3.4.3 增档评估**：每增 1 档约 +48 二进制变量（12 月×4 班次组合…实际 +36），先 `test_mode_constraints.py` 式压测求解时间。优先给波动最大的车间增档（看 `plan_*.csv` 档切换频率）。

**3.4.4 OEE 拆分**（与 `avail` 混装问题一并解）：`avail = time_rate × perf_rate × quality_rate` 三表，MES 停线→time，能耗/节拍→perf，FTT→quality。偏差追溯时直达责任方。

### 3.5 业务与组织动作

IE 定 `combo_factor/ramp` 初值并季度标定；设备给停线分类；质量给 FTT。AI&Data 交付标定脚本（历史反推）+ 敏感性报告（系数 ±5% 对总成本影响）。

### 3.6 风险与应对

| 风险 | 应对 |
|---|---|
| 系数拍脑袋 | 历史反推 + 置信区间，不确定取保守（低 factor） |
| 求解变慢 | 增档前压测；超时则时限截断 + 记次优标识 |
| 系数打架（组合与爬坡叠乘过低） | 设下限 0.6，超限告警人工看 ⚠ |

### 3.7 验收与 KPI

复杂月偏差收窄（如 MPE 降 30% ⚠）；爬坡期零"排产爆掉"；求解时长 P90 不增超 50%。

### 3.8 工作量与依赖

系数法 2–3 周；增档 + 压测 1 月。依赖拓展 1（历史实际 JPH）。

## 拓展 4：从成本到利润——缺口惩罚改边际贡献

### 4.1 现状与证据

`shortage_penalty` 基准 3 万/台；策略扫 0.3 万（缺 10878 台）/20 万（零缺口，多花 4022 万，约 3700/台）。已证明**惩罚定缺口**，但惩罚值无依据。

### 4.2 核心问题

真实决策看边际利润 `margin = 售价 − 物料 − 物流 − 变动制费`，不是统一惩罚。不同车型 margin 差数倍，一刀切惩罚会杀错车型。

### 4.3 总体思路

目标改为 `min 总成本 − Σ margin[m]×交付[m,t]`（等价按车型设惩罚 `pen[m]=margin[m]`），或约束 `Σ short×margin ≤ 利润缺口预算`。财务给 margin，计划给优先级。

### 4.4 详细设计

**4.4.1 新表 `margin.csv`**：`{model, month, margin_per_unit}`。口径（⚠ 财务定）：售价 − 物料（BOM×单价，拓展 6 前先用标准成本）− 物流 − 变动制费。月度更新（价格/汇率调）。

**4.4.2 目标改写**（二选一，先 A）：

```
A: min 成本 − Σ margin·x[S[-1],m,t]   （交付越多目标越小，自动保高margin车）
B: min 成本 s.t. Σ short·margin ≤ 预算  （利润缺口封顶）
```

A 改动最小（`build()` 目标加一项，`short` 可保留作指示）。B 适合"缺口金额红线"管理。

**4.4.3 优先级**：内销/出口/大客户加权 `priority[m,t]`，惩罚 `= margin × priority`。船期前月份权重上浮（与拓展 2 周模型衔接）。

**4.4.4 报表**：`strategy_summary` 加"缺口利润损失 = Σ short×margin"，与"补齐成本 4022 万"并列，管理层直接比大小。

### 4.5 业务与组织动作

财务定 margin 口径并月度发布；销售给售价/优先级；计划执行。AI&Data 交付 margin 敏感性（±20% 看缺口结构变不变）。

### 4.6 风险与应对

| 风险 | 应对 |
|---|---|
| margin 涉密 | 分级可见（管理层看值，执行层只看排序） |
| 物料价波动大 | margin 月度版 + 冻结机制（测算用发布版） |
| 低 margin 车永远被缺 | 加"保底交付比"约束（如每车型 ≥80% 需求 ⚠） |

### 4.7 验收与 KPI

缺口结构与 margin 排序一致；管理层例会用"补齐成本 vs 利润损失"决策；零"杀错高利润车"投诉。

### 4.8 工作量与依赖

目标改写 1 周 + margin 口径会 2–3 轮。依赖财务物料口径（拓展 6 可并行先行版）。

## 拓展 5：从确定到随机——稳健性做到日常

### 5.1 现状与证据

`monte_carlo()` 已验证：成本方案 20 次 18 缺 vs 稳定 0 缺；`fix_y` 锁档重优链路现成。但只在策略评估跑，月度基准无体检。

### 5.2 核心问题

确定最优在波动下最脆弱（98.6% 利用率 = 零缓冲）。管理层每月拿到的是单点答案，没有"风吹草动会怎样"。

### 5.3 总体思路

需求给区间（P50/P90）→ 方案每月体检（锁档重优）→ 余量变日常参数。三件套全部复用现有函数，只包报表层。

### 5.4 详细设计

**5.4.1 需求区间**：小模型输出 `demand_P50/P90`（拓展 7 前先用 ±8% 均匀带代替，`monte_carlo(spread=0.08)` 现成）。基准用 P50 求解，P90 做体检。

**5.4.2 方案体检**（新增 `health_check.py` 包 `monte_carlo`）：输入某方案 `fix_y`，输出体检表：

```
平均成本 / P90成本 / 平均缺口 / 最大缺口 / 有缺口样本占比
+ 按月缺口热力（哪月最脆）+ 首个击穿车间
```

每月基准附体检表，与 `plan_基准.csv` 同发。

**5.4.3 余量日常化**：`util_cap` 从策略包下放为车间参数 `util_target[s]`（如 BIW 0.9、TCF 0.88 ⚠），`ot` 上限分"日常 24 / 旺季 36"两档（旋钮现成）。月度滚动时按季节切档。

**5.4.4 升级（二期）**：两阶段随机规划（第一阶段定 y，第二阶段 ot/x/inv 随场景）——求解量 ×N 场景，待商用求解器（拓展 8）后再议。

### 5.5 业务与组织动作

计划定体检阈值（如缺口率 >20% 必须切稳定方案 ⚠）；管理层月度看体检表拍余量。AI&Data 交付体检报表模板 + 击穿归因（一句话：哪月、哪个车间、差多少）。

### 5.6 风险与应对

| 风险 | 应对 |
|---|---|
| 体检增加 20 次求解时间 | 降采样（10 次）+ 并行 + 只检基准与备选（2 方案） |
| 区间被当承诺 | 标注"体检带非预测"，P90 缺口≠会缺口 |
| 余量被层层加码 | util_target 按车间定死，调整走变更（C4） |

### 5.7 验收与 KPI

每月基准 100% 附体检表；缺口率超阈方案 100% 有处置（切档/加余量/书面接受风险）；年缺货事件数趋势降。

### 5.8 工作量与依赖

体检包装 1–2 周。依赖拓展 1（真实需求波动带标定 spread）。

## 拓展 6：从人工能源到全成本——物料 80% 与物流阶梯

### 6.1 现状与证据

模型单车 3579 元仅含 7 科目（人工/能源/班车/外包/加班/OH/持有）；物料约 80% 未进目标（只作 `supply` 缺料约束）；物流零建模。要素拆解 §15.5 已预留物流设计。

### 6.2 核心问题

单车口径与财务对不上（管理层会问"3579 vs 财务单车差 10 倍？"）；排产波动的真实代价（加急运费、库存资金）看不见。

### 6.3 总体思路

物料先进变动单价（BOM×单价，单价月版），缺料走现有 `supply`；物流加整数趟次变量（阶梯成本）。分两步：先物料（1 月见效），后物流（1 季度）。

### 6.4 详细设计

**6.4.1 物料四表**（真实系统；原型先 2 表简化）：

```
bom.csv: {model, part, qty_per_unit, eff_from, eff_to}
part_price.csv: {part, month, price}
→ mat_cost[m,t] = Σ qty×price，进 var_cost_per_unit
```

原型简化：`mat_cost_per_unit.csv: {model, month, cost}` 直接给单车物料费（财务标准成本），先跑通再拆 BOM。

**6.4.2 物流阶梯**（按 §15.5）：

```
新变量 trips[l,mode,t] ∈ 整数（线路l, 方式mode, 月t）
约束：运量[m,t] ≤ Σ trips × 容量(如8台/趟)   （运量↔x[S[-1]]关联）
成本：Σ trips×趟费 + 包车0/1×月费
```

入厂 JIT 取货同理（趟次+包车）。先整车发运（数据最齐），后入厂。

**6.4.3 库存资金**：成品/在制 `inv` 加资金成本 `× 月利率`（与持有成本合并或单列 ⚠ 财务定）。

**6.4.4 规模影响**：`trips` 整数约 线路×方式×12（<100），可接受。物料进目标不增变量，只改系数。

### 6.5 业务与组织动作

采购给零件价 + 供应能力（`supply` 上限口径化）；物流给线路/趟费/容量；财务定单车口径（模型口径 vs 全成本对照表）。AI&Data 交付 BOM 展开脚本 + 物流子模块。

### 6.6 风险与应对

| 风险 | 应对 |
|---|---|
| BOM 量大（万级零件） | 先总量（单车物料费），再 Top20 关键件明细 |
| 价格月月变 | 月版冻结 + 测算用发布版 |
| 物流数据散（承运商） | 先自营/主干线，后支线包车 |

### 6.7 验收与 KPI

单车口径对照表发布（差解释 100%）；波动月加急运费显性化；缺料约束 `supply` 覆盖 Top 关键件。

### 6.8 工作量与依赖

物料简化版 2–3 周，BOM 全拆 1 季度；物流 1 季度。依赖采购/物流数据（与拓展 1 并行启动）。

## 拓展 7：从求解到解释——LLM 与 Laya 日常化

### 7.1 现状与证据

解释靠手写（§1A.2 总装 10 月、§0B.2）；LLM/Laya 只有 §13/16/19 设计，未接原型。`plot_*` 图齐，但"为什么"仍需人工讲。

### 7.2 核心问题

结果是一堆数字，管理层问"为什么 10 月加班"要等 2 天；场景"如果…会怎样"说不清、口径各算各的。

### 7.3 总体思路

先规则后 LLM：模板解释器自动填数+出处（确定性），LLM 只润色措辞；自然语言只做旋钮翻译（不算数）；Laya 只做判断分流（不求解）。三权分立，全部留痕。

### 7.4 详细设计

**7.4.1 模板解释器**（新增 `explain.py`，先做，不碰 LLM）：

```
输入：plan/cost/参数快照
规则链：需求(何值/何版本) → 日历(几天) → 产能(档×班→正常产能) → 缺口(÷JPH→加班h/上限) → 比选(次优贵在哪三项) → 结论
输出：一段话 + 每句出处[表名/版本/数值]，如：
"10月总装加班35.6h[plan_基准.csv:TCF,10]，因需求11000[demand.csv v3]超正常产能9720[36×7.5×2×18]，
 缺口1280÷36=35.6≤36[shop_params v2]；30×3班贵147万[scenario比选]，主因人工+207万。"
```

**7.4.2 自然语言→旋钮**（`nl_to_knobs()` + LLM）：

```
"10月需求+25%，总装要不要三班" → {"demand_cell":{"10|V446K":1.25,...}} 草稿
→ 人确认（界面勾选）→ apply_knobs → 重解 → explain
旋钮表达不了 → 明确回"需新旋钮：XX"，不硬凑（预期管理）
```

先做关键词模板（月/车型/±%/三班），命中率 >80% 再上 LLM（§13.1 调研结论）。

**7.4.3 RAG 问答**：口径文档 + 参数说明 + 变更记录 + 历史解释入库；回答附引用（"定员随档单调[口径字典 v5]"）。

**7.4.4 Laya 四用**（阈值示例 ⚠，历史场景验证后定）：

| 用 | 类型 | 输入→输出 | 阈值处置 |
|---|---|---|---|
| 场景识别 | choice | 事件描述→{缺芯/波动/停线/限电} + 概率 | ≥0.8 套模板，<0.8 人工选 |
| 风险把关 | noul | 方案→{超加班/溢存/违规？}概率 | 高拦、中复核、低过 |
| 策略推荐 | score/choice | 订单确定性/库存/人力→推荐策略 | 只建议，管理层拍 |
| 异常分级 | score | 偏差/变更→紧急度 | 自动修/通知/升级 |

部署本地/私有云，数据不出厂；决策留痕挂实体（输入/选项/概率/阈值/路径）。

### 7.5 业务与组织动作

计划定义常用问法 Top20（解释器优先覆盖）；业务 Owner 定拦截阈值；中心团队维护知识库。节奏：解释器随每次测算出，RAG 双周补料。

### 7.6 风险与应对

| 风险 | 应对 |
|---|---|
| LLM 胡编数字 | 数字全部来自模板/求解器，LLM 只润色；出处强制附 |
| 阈值误拦/漏拦 | 先影子运行（只记录不拦截）1 月再上线 |
| 知识库过时 | 变更记录自动入库 + 月度 review |

### 7.7 验收与 KPI

管理层提问 5 分钟出带出处解释；场景响应分钟级（常规）；解释采纳率（业务点"对"占比）；拦截准确率（事后复核）。

### 7.8 工作量与依赖

模板解释器 2–3 周；NL 模板 2 周，LLM 版 1 月；Laya 试点 1 季度。依赖拓展 1（口径字典、版本）。

## 拓展 8：从 CSV 到平台——工程化四件事

### 8.1 现状与证据

CSV + 本地 PuLP 2.9 + CBC/HiGHS + 30–60s 时限；`run.py` 约 1 分钟 5 场景，`stress_test.py` 23 解约 4–5 分钟。权限/调度/并发/结果库全无。

### 8.2 核心问题

个人工具变部门系统差四门：数据源、求解能力、权限、调度。任一缺位都上不了线。

### 8.3 总体思路

表结构不变（CSV↔数仓同构），`data_loader` 加分支；求解器先压测再选型；权限按"工厂×角色"隔离；调度"月自动+场景按需+对账定时"。

### 8.4 详细设计

**8.4.1 数仓分支**：

```python
def load(data_dir=None, source="csv", month=None):
    # source="db": 从数仓读，SQL按(场景ID, 月份, 生效日期)过滤，字段同CSV
```

ODS→DWD→参数层映射：PLM→BOM/工时，MES→产量/开动/停线，HR→定编/出勤/加班，能源→计量，财务→实际成本/口径。调度：参数层 T+1，基准月度自动，对账月结后 N 日 ⚠。

**8.4.2 求解器选型压测矩阵**（⚠）：

```
规模：1厂(430二进制) → 3厂并行 → 车型×2 → 月份滚动18
求解器：CBC / HiGHS / 商用(Gurobi/COPT⚠许可证)
指标：P50/P90时长、内存、最优 gap、时限截断率
结论模板："X规模下HiGHS P90 __s，可用；超Y规模需商用/分解"
```

**8.4.3 权限矩阵**：

```
参数读：本部门相关列；写：负责人；工资明细：HR+管理层；成本汇总：计划/财务/管理层
跨厂：只看汇总指标（单车/利用率/缺口），明细不出厂
```

**8.4.4 结果库**：`results{场景ID, 核心/配置/参数/方法版本, plan, cost, 解释, 决策单}`，任一历史一键重算（块 2 验收）。

### 8.5 业务与组织动作

IT 给数仓资源 + 安全评审；业务 Owner 定权限 matrix；中心团队做压测报告。里程碑：数仓分支→压测→权限→调度，每步可独立验收。

### 8.6 风险与应对

| 风险 | 应对 |
|---|---|
| 商用许可证贵/批不下 | HiGHS 先行 + 分解（按厂解耦，缓存周转除外） |
| 数仓排期长 | CSV 并行（文件网关过渡），接口先行 |
| 并发打爆 | 队列 + 时限 + 降级（超时返回次优+标识） |

### 8.7 验收与 KPI

三厂并发 P90 达标 ⚠；历史一键重算 100%；权限审计 0 越权；调度准时率。

### 8.8 工作量与依赖

约 1 季度，需 IT 0.5 人。依赖拓展 1（表结构冻结）。
