## 4. 核心逻辑复述（0B 十四步浓缩 + TCF 10 月例）

```
Ⓐ快照：场景ID+生效日期冻结一份参数（需求/配置/产能时间/单价规则/旋钮改写）
Ⓑ匹配：所需产量 → 候选 JPH档×班次 → 正常产能=JPH×小时×班次×天数(×开动率⚠)
       → 够？做 : 缺口/JPH≤36h？加班 : 升档/加班次/吃缓存/认缺口
       → 车间链流平衡（上月存+上游做=下游用+本月存）
Ⓒ成本：选档即定人定功率 → 人数=定员×班次 → 人工/加班/能源/班车外包/OH/持有
Ⓓ决策：硬约束剔除 → MIP 联解 → 策略场景压力 → 可接受？拍板留痕 : 回Ⓑ换策略
       → 执行（月→周→日，不可行回新约束）→ 对账（±5%⚠示例）→ 回写Ⓐ
```

TCF 10 月（示例）：需求 11000、上限通过、18 天 → 36×2：270h→9720→缺 1280→加班 35.6h→850 人→1449 万（单车约 1317）；30×3 要 1596 万（贵 147 万），故选 36×2。四车间 12 月联解，11–12 月涂装经 PBS 调 880 台。详见要素拆解 §1A.2–§1A.4、§0B.2，计算模型 §18。

## 5. 十个深入拓展方向（每个：现状 → 缺口 → 做法 → 验收）

### 拓展 1：从示例数据到真实数据——参数映射与首次对账（最高优先级）

- **现状**：`data/*.csv` 9 表全齐，TZ 就绪度 L2（可测算、缺 `actual.csv`），DEMO_B L3（含故意 −15.5% 埋点演示追溯）。`plant_check` 27 项全 PASS。
- **缺口**：真实工时/定员/单价/上限/日历无人认领、无版本、无来源；测算从未与 MES/财务对过账。
- **做法**：
  1. 按项目总结 §5.1 归属表认领（工时/JPH→IE，工资/加班→HR，电价→能源，OH/班车外包→财务，上限/日历/需求→计划）；
  2. 三类参数搬数仓（产能限制配置 + 工资/加班 + 能源），带版本/生效/负责人；
  3. `run_plant.py` 回测最近 3–6 个月，偏差超阈值（示例 ±5% ⚠）追到开动率/工时/单价并修参数发新版。
- **验收**：过期参数数为 0；首份月度偏差报告（车间 × 科目 × 月）经财务签认。对应合作稿试点"4–6 周见效"。

### 拓展 2：从月度到周/日——分层计划（月定档、周排班、日排人）

- **现状**：月度 `y` + 连续 `ot/x/inv` 联解；下层（周班组、日人员）只有接口设想（0A-L2 LOW 节点），`shift_quarter/jph_step` 只是近似。
- **缺口**：月方案落不了地（某技能不够、班车排不开）无处反馈；排序/换色/间隔规则在月层表达不了。
- **做法**：月模型输出 `(JPH档, 班次, 产量)` 冻结为周模型边界；周做班组排班 + 车型排序（Car Sequencing：连续 N 台中高工时 ≤K 台、涂装换色批量）；日做人员点名。周/日不可行（如某工种缺 5 人）回写为 `y` 禁用或 `cap` 扣减，重解月模型（绿色虚线）。
- **验收**：连续两月"月方案一次下达成功率"达标 ⚠；不可行反馈有单可查（C7）。

### 拓展 3：从离散三档到"档 + 微调"——JPH 精细化与组合折损

- **现状**：每车间 3 档，档内无级差；组合复杂度不打折 JPH（§5 缺口）。
- **做法**：短中期加 `combo_factor[组合]`（有效 JPH = 档 JPH × 系数）+ `ramp[(s,t)]` 爬坡打折；中长期按瓶颈工位实测增档（如 TCF 加 33 档）或引入半连续 `jph_cont` + 定员分段函数。注意：加档线性增加 `y` 规模（每档 +48 二进制），先测求解时间。
- **验收**：旺季组合复杂月的测算↔实际偏差收窄；爬坡前 3 月不再系统性乐观。

### 拓展 4：从成本到利润——缺口惩罚改边际贡献

- **现状**：`shortage_penalty` 3 万/台（基准），策略扫 0.3 万/20 万/台，证明"惩罚定缺口"（§17/§10）。
- **缺口**：惩罚是拍脑袋的；真实决策看边际利润（售价 − 物料 − 物流 − 变动制费）。
- **做法**：`supply` 侧加 `margin[m]`（车型边际贡献），目标改为 `min 成本 − margin×交付`，或约束 `short×margin ≤ 预算`。财务给 `margin` 口径（含物料 80% 大头 ⚠ 当前模型未含物料），计划给交付优先级（内销/出口/大客户）。
- **验收**：管理层能回答"多花 4022 万补 10878 台值不值"（当前约 3700/台 vs 真实 margin）。

### 拓展 5：从确定到随机——稳健性做到日常

- **现状**：蒙特卡洛已验证"成本 18/20 缺 vs 稳定 0 缺"（`montecarlo_summary.csv`），但只在策略评估时跑。
- **做法**：日常化三件套：① 需求区间（P50/P90）代替单点（小模型输出分布）；② `fix_y` 锁档重优 ot/x/inv 做"方案体检"（已有 `monte_carlo()`，包一层报表）；③ 关键约束加安全余量（`util_cap` 从策略包变为日常参数，按车间设 0.85–0.95 ⚠）。
- **验收**：每月基准附"±8% 波动体检表"（平均/ P90 / 缺口率），稳定方案有例行出口。

### 拓展 6：从人工能源到全成本——物料 80% 与物流阶梯

- **现状**：模型只含人工/能源/班车/外包/加班/OH/持有（单车 3579 元是模型口径，非全成本 ⚠）；物料占单车约 80% 未进目标（只作约束 `supply`）；物流未建模。
- **做法**：物料：`BOM(车型,零件,用量,生效)` × `零件价` 进变动单价，缺料走 `supply` 约束（已通）；物流：整数 `trips[线路,方式,月]` + `运量 ≤ 趟数×容量(8台/趟示例)` + 趟费/包月费（要素拆解 §15.5 预留设计）。
- **验收**：单车口径与财务对上（差解释清单）；排产波动→加急运费显性化。

### 拓展 7：从求解到解释——LLM 与 Laya 日常化

- **现状**：解释靠手写（§1A.2/0B.2），LLM/Laya 只有设计（§13/16/19），未接原型。
- **做法**：① 模板化解释器（先规则后 LLM）：沿实体链（需求→日历→产能→加班→成本）自动填数 + 出处（参数版本），LLM 只润色；② 自然语言→旋钮（"10 月 +25% 要不要三班"→`demand_cell` 草稿→人确认→重解）；③ Laya 四用：场景识别 choice、风险把关 noul（超加班/溢存/违规拦）、策略推荐 score、异常分级 score，阈值 0.8/0.5 先验证再上线 ⚠。
- **验收**：管理层提问 5 分钟内出带出处解释；场景响应分钟级（C3/C5 KPI）。

### 拓展 8：从 CSV 到平台——工程化四件事

- **现状**：CSV + 本地 PuLP + 30–60s 时限，权限/调度/并发全无。
- **做法**：① 数仓替代 CSV（`data_loader` 加数仓分支，表结构不变）；② 求解器选型（开源 CBC/HiGHS vs 商用 ⚠，规模翻倍压测：车间×车型×月）；③ 权限（参数读写按部门/工厂隔离，工资敏感列脱敏）；④ 调度（月度基准自动跑 + 场景按需跑 + 对账定时跑），结果库带版本可追溯。
- **验收**：三厂并发下 P90 求解时长达标 ⚠；任一历史结果一键重算。

### 拓展 9：从单厂到多厂——把 W1 落地

- **现状**：机制已设计（§21）、原型已验证（TZ L2 + DEMO_B L3），缺真实第二厂。
- **做法**：按 §21.5 六步 + 就绪度六维选"最像台州"的灯塔厂（A 档 2–3 月）：评估→映射（LLM 建议字段映射）→配置（复制 TZ 包改）→回测→并行 1–2 月→上线。需求经 CAB 回流（通用进核心、特有进配置），禁私改核心。
- **验收**：推广 KPI 首测：单厂周期、中心投入、配置化率、适配器复用率、回测偏差、key user 认证数（§21.8，目标待定 ⚠）。

### 拓展 10：从项目到运营——组织与 KPI 闭环

- **现状**：C1–C12、RACI、双周/月度节奏已在纸面（§20），未运转。
- **做法**：① 联合项目组 + MBO/立项（合作稿 §3/§9）；② 双周例会（进度/问题/对账）+ 月度管理层简报（策略对比/偏差/风险）；③ KPI 三层：模型质量（偏差率/超阈数）、效率（场景响应/对账时效）、业务（计划达成/加班/缺口/单车趋势）。阈值全部 ⚠ 待定，先跑三月再定。
- **验收**：连续三月完成"发布→测算→对账→校准"循环（C12 使用率 100%）。
