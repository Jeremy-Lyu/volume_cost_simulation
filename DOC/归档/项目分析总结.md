## 1. 背景：为什么做这个项目

### 1.1 业务起点：VCS demo 已经很好
业务部门已在台州工厂做出 VCS（产量成本测算系统）demo：

- 把 **JPH、人力、能源、排产、车型配置与 BOM、设备** 连在同一个模型里；
- **JPH 按车间分别设定**：冲压 STP → 焊装 BIW → 涂装 PNT → 总装 TCF，车间之间用缓存（WBS/PBS）衔接；
- **用优化求解**：不只是方案对比，而是在约束下求成本最低的 `JPH档 × 班次` 组合；
- 功能锚点清晰：「产能限制配置」表 + 成本测算六模块（能源、制造费用 OH、班车、工资、服务外包、加班费）+ 「假设 JPH 测算总览」；
- 已有策略视角：成本优先 / 稳定优先 / 保人力 / 保交付。

### 1.2 痛点假设（待阶段 0 核实，不是定论）
同类工具常见问题，合作稿列了 7 条待核实：参数散在手工 Excel、更新频率和负责人不清、从未与 MES/财务实际对账、写死单工厂结构难扩到 3 厂、规模大了求解慢、结果难解释、场景响应慢。

### 1.3 AI & Data 组的进入方式
定位是**共建方，成果归业务**，总体筹划为吕吉。路线是：

```
联合诊断（2周）→ 参数入数仓+首次对账（4-6周见效）→ 平台化+小模型试点（一季度）→ 智能决策+多工厂
```

原则：**数字由求解器和规则算，AI 只做预测/判断/解释，不直接改生产数据**；小步快跑，每阶段由业务决定是否继续。

### 3.3 关键结果（示例数据）

- **基准**：总成本 42953 万元，年产 12 万台，零缺口，单车 3579 元（仅模型科目）；以“中档 JPH + 两班”为主，旺季 5/10/11/12 月升档。
- **灵敏度**：需求 +10% → 总成本 46004 万但单车降至 3485 元（固定摊薄）；需求 −10% → 单车升至 3677 元；电价 +20% / 工资 +5% 本例不换班次。
- **策略价格**：稳定优先 45484 万（+5.9%，换 10% 余量）；保人力 44033 万（+2.5%）；需求 +20% 低惩罚时宁可缺 10878 台，高惩罚 20 万/台时多花 4022 万补足。
- **稳健性**：需求 ±8% 蒙特卡洛 20 次，成本优先 18 次缺货，稳定优先 0 缺货（每年多约 2000 万买不缺货）。
- **极限**：焊装 6 月停线 0→10 天靠“加班→升档→5 月预产 + 缓存”吸收；全局需求约 1.3 倍后旺季开始缺货。
- **多工厂验证**：虚构 `DEMO_B`（焊装→涂装→总装、单车型）Optimal，总成本 19947 万，单车 4123 元；回测 36 个车间×月中 1 个超阈（涂装 8 月 −15.5%，故意埋点演示追溯）。

## 4. 意义：三层价值

1. **决策语言统一**：模型是“如果…那么…”，把争论从“谁的 Excel 对”变成“哪个假设该改”。给管理层的不是一个数，而是各策略的成本/风险/取舍 + 假设留痕。
2. **数据资产复用**：同一套车型/车间/日历/单价可复用到单车成本、产能规划、物流；参数入数仓 + 对账是后面一切的前提。
3. **规模化可能**：`核心标准 + 工厂配置包`：实体/表结构/求解结构/接口/口径是核心，车间链/JPH/班次/费率/规则是配置。新厂走上线六步，按就绪度分档分波次，AI 做映射/抽参/解释加速。

## 6. 各模块如何合作运作（一次测算的数据流）

```
场景旋钮 → 参数快照 → 子模块算成本表 → 主模型选方案 → 结果库 → 报表/解释 → 决策 → 对账回写
```

| 模块 | 文件 | 输入 → 输出 |
|---|---|---|
| 参数层 | `data/*.csv` + `data_loader.py` | 需求/日历/上限/JPH/班次/单价 → 参数字典 `d`；`validate()` 做完整性校验 |
| 场景层 | `scenarios.py` + `scenario_library.csv` | 旋钮（需求系数/avail/down/supply/elec/wage/ot）→ `apply_knobs` 覆盖参数 |
| 成本子模块 | `cost_functions.py` | （车间,JPH档,班次,月）→ 人数/班车/外包/固定能耗/加班单价/变动单价（只算，不管选） |
| 主模型 | `model_builder.py` | 查成本表 + 约束（产能/需求/流平衡/缓存/加班/供应）→ 选 `y[JPH档×班次]` + `ot/x/inv/short`，目标总成本 + 缺口惩罚最小 |
| 报表 | `report.py` | 求解值 → `plan_*.csv`（JPH/班次/人数/加班/产量/利用率）、`cost_*.csv`（分科目） |
| 策略/压力 | `strategies.py`、`stress_test.py` | 换约束（util_cap/head_change/惩罚）或扫旋钮 → 对比表 + 图 |

车间链联动靠**流平衡约束**：上月缓存 + 上游本月产量 = 下游本月产量 + 本月缓存，`0 ≤ 缓存 ≤ buffer_cap`，有持有成本。所以各车间可各选各的 JPH/班次（如 11 月涂装多做 880 台存 PBS，12 月少做、下游照做）。

## 7. 重点：人力和 JPH / 产线人数到底怎么算

### 7.1 核心结论（一句话）
**人数不是按工时公式临场算的，而是“选档即定人”**：每个 `车间 × JPH档` 在 `jph_options.csv` 里绑定一个**每班定员**，选了哪个档、开几个班，人数就定了。求解器只是在离散档位里选，不会算出 “JPH 33.7、791 人” 这种中间值。

### 7.2 输入表（原型当前值，示例数据）

`jph_options.csv`（车间, JPH, 每班定员, 运行功率 kW）：

| 车间 | JPH 档 → 每班定员 / 功率 |
|---|---|
| 冲压 STP | 30→40人/900kW；40→50人/1150kW；50→62人/1400kW |
| 焊装 BIW | 24→180人/1500kW；30→215人/1800kW；36→255人/2100kW |
| 涂装 PNT | 24→90人/3500kW；30→105人/3900kW；36→122人/4300kW |
| 总装 TCF | 24→300人/700kW；30→360人/850kW；36→425人/1000kW |

`shift_options.csv`：1 班/2 班每班 7.5h，班车 6 万/班/月、外包 8 万/班/月、无夜班补贴；3 班每班 7.0h，班车 7.5 万、外包 9.5 万、夜班补贴 800 元/人（只在 3 班加）。

`global_params.csv`：工资 9000 元/人/月，加班 75 元/人·时，电价 0.75 元/kWh。`shop_params.csv`：加班上限 36h/月。`calendar.csv`：如 10 月 18 天。

定员随 JPH 单调递增是质量规则（`plant_check` 会查）， vocab 上这就是**线平衡方案的定员表**：JPH 背后是一套工位划分和人员配置。

### 7.3 公式（`cost_functions.py` 原样）

```
月开动小时 = 每班有效小时 × 班次数 × (工作日 − 该车间停线天数)
正常产能 = JPH × 月开动小时 × 开动率系数（场景旋钮，默认 1）
人数 = 每班定员 × 班次数
人工月成本 = 人数 × 工资 + (3班时：每班定员 × 夜班补贴)
加班1小时成本 = 每班定员 × 加班单价 + 运行功率 × 电价
```

注意两点原型简化：① 人数没有除以出勤率（出勤影响 folded 进 `avail` 开动率旋钮）；② 夜班补贴只按**一个班**定员算（`o[heads]×800`），不是总人数，解读时按此口径。

理论对照（文档块 7）：`直接人数 ≈ 单车标准工时 × JPH / 人员效率 × 班次 / 出勤率`。原型把这个换算**预固化**在定员表里，IE 改线平衡即改表，不用改代码。

### 7.4 手算实例：总装 10 月（JPH36 × 2 班）

| 步 | 算式 | 结果 |
|---|---|---|
| 取数 | 需求 4620+3630+2750；工作日 18；JPH36 定员 425/1000kW；2 班 7.5h | — |
| 可用小时 | 7.5 × 2 × 18 | 270h |
| 正常产能 | 36 × 270 | 9720 台 |
| 缺口/加班 | (11000−9720)/36 | 35.6h（≤36，可行） |
| 人数 | 425 × 2 | **850 人** |
| 人工 | 850 × 9000 | 765 万 |
| 加班费 | 35.6 × 425 × 75 | 113.3 万 |
| 班车/外包 | 2×6 万 / 2×8 万 | 12 万 / 16 万 |
| 当月总装合计（含能耗 OH） | 见 1A.2 | 1449 万，单车约 1317 元 |

同理：焊装 30×2 班人数 `215×2=430` 人，人工 387 万；冲压 50×1 班人数 `62×1=62` 人，人工 55.8 万。**JPH 越高，定员越大**，但分摊到每台未必贵——求解器比的是整月总账（含加班 vs 多开一班）。

### 7.5 为什么 36×2 班打败 30×3 班（总装 10 月）
30×3 班不用加班，但人数从 850→1080（+207 万工资）+ 夜班补贴 28.8 万 + 多一班的班车外包约 23 万 + 固定能耗约 4 万，合计多约 263 万，远超 36×2 班的加班成本约 116 万。所以贵约 147 万。**这就是离散档位的取舍**：连续可调会低估成本，离散才有“加班补一点 vs 多开一班”的跳变。

### 7.6 人力模块与上下游的协作

- **上游**：IE 给定员表、日历给工作日、场景给停线/开动率 → 决定产能；需求给产量目标。
- **本模块**：输出人数 + 人工 + 加班单价给主模型。加班上限（36h）是硬约束，超了只能升档/加班次/留缺口。
- **下游**：班次同时驱动班车、外包、固定能耗（开动即耗），所以人力决策会联动能源和 OH。`head_change`（人数月环比 ≤5%）和 `shift_quarter`（班次按季固定）是可选的“稳定/保人力”约束，加上后冲压被迫用 `30×2` 代替 `50×1`，多花 41 万——这就是灵活性的价格。
- **对账**：HR 实际人数/加班 vs 测算，偏差追到定员、开动率或单价，再回写参数。

### 7.7 简化与待确认（⚠）
原型未做：技能矩阵/出勤率分开建模、招聘提前期 1–3 个月、间接人员、周末/平日加班异价、两班 12h 模式（需把班次主键从班次数改为模式 ID）、爬坡/换型/排序。人力按定员还是按工时、能源是否分峰谷，都需业务确认。

## 8. 局限与下一步

- 求解时限 30 秒/次，个别场景可能非严格最优（如出口场景 6 台缺口看量级即可）。
- 开动率系数混装了设备/出勤/限电，未分开；无周末加班/外协/跨厂调产独立选项。
- 下一步按合作稿：阶段 0 先回答 12 个诊断问题，试点选“参数入数仓 + 首次对账”（台州四车间、产能限制 + 工资/加班 + 能源三类参数，4–6 周），再谈小模型与多工厂。
